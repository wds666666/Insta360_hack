### 6.3 网络切换限制

当前端到端流程可用，但现场操作需要分成两个网络阶段：

1. Mac 连接 Insta360 X5 热点，访问 `192.168.42.1` 完成拍摄、机内拼接、下载与本地投影。
2. 拍摄候选图全部落盘后，切换到能够连接互联网的 Wi‑Fi。
3. 在页面确认视角并提交，继续调用 DeepSeek、OpenRouter/Gemini 与 Lux3D。

该限制的本质是相机热点与互联网出口不能同时稳定可用。系统当前设计已经把拍摄数据先保存到服务端，因此切换网络不会丢失照片；用户只需在拍摄成功后恢复互联网再提交。

历史记录中两次 capture 驱动的 run 曾因 DNS/网络不可达失败，错误分别出现在空间理解和后续网络调用阶段；恢复互联网后，同一拍摄结果可以重新提交并成功生成 GLB/STL。这与当前操作约束完全一致。

## 7. 风险与改进建议

| 优先级 | 项目 | 影响 | 建议 |
|---:|---|---|---|
| **P1** | X5 热点与互联网 Wi‑Fi 需人工切换 | 演示时可能误在离线状态提交，导致第三方调用失败 | 页面在拍摄成功后增加互联网连通性检测；离线时禁用提交并提供一步式提示 |
| **P1** | 网络恢复后需人工重提失败任务 | 增加操作成本 | 为 `NETWORK`/DNS 类失败提供“恢复网络后重试”入口，复用已落盘 capture 与 run 输入 |
| **P2** | 前端主 JS 包 846.36 kB | 首屏加载和低性能设备体验受影响 | 懒加载 Three.js/GLTFLoader，拆分查看器与主表单代码 |
| **P2** | 前端缺少组件级自动化测试 | UI 回归依赖构建与冒烟检查 | 引入 Vitest + Testing Library；优先覆盖 PromptForm、X5CapturePanel、StageList、API 错误映射 |
| **P2** | 测试依赖出现 2 条弃用警告 | 后续升级可能破坏测试环境 | 锁定兼容版本或迁移到推荐的 TestClient/httpx2 与 AnyIO 接口 |
| **P3** | 现有 capture/run 记录包含调试失败数据 | 演示任务列表可能显得杂乱 | 增加归档/筛选能力，演示环境使用独立数据目录 |

### 7.1 推荐的网络体验优化方案

短期建议采用“状态提示 + 连通性门禁”，投入小、收益高：

- X5 拍摄成功后显示醒目的“双阶段网络”引导。
- 后端提供轻量健康检查，分别标识“X5 可达”和“互联网/第三方 API 可达”。
- 在互联网不可用时保留 capture，禁止启动 AI run，避免生成可预防的失败记录。
- 网络恢复后允许一键继续，不要求重新拍摄。

中期可评估双网卡或路由方案，例如 Wi‑Fi 连接 X5、USB/以太网/手机热点提供互联网出口，但需要对 macOS 路由优先级、VPN 与 `192.168.42.1` 私网冲突进行专项验证。
